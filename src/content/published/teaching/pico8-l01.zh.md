## 本课的问题

第一次代码课需要让抽象概念尽快产生可观察的结果。原始教案从绘制矩形开始，再引入变量、按钮输入与移动，之后预备了碰撞和平台跳跃。这里保留这一递进顺序，但不把教案中的全部预备内容当作已经讲授完成。

学习目标是让学生能指出：输入在哪里读取，位置在哪里保存，画面又在哪里使用这个位置。只要能解释这三处关系，一个很小的例子也能成为之后调试和扩展的基础。

## 从静态矩形到交互

先只画一个矩形，改变坐标和颜色参数，观察画面变化。接着将横坐标改为变量，最后在更新中根据输入修改它。下面是依据教学目标重新整理的最小示例，不是课堂代码的逐字记录：

```lua
function _init()
 x=60
end

function _update()
 if btn(0) then
  x=x-1
 end
 if btn(1) then
  x=x+1
 end
end

function _draw()
 cls(0)
 rectfill(x,60,x+7,67,7)
end
```

让学生先预测一次修改的结果，再运行验证。示范左右移动后，可以暂停讲解，让同学自己补充纵向移动；此时不需要立即增加重力、碰撞与动画。

## 更新与绘制的职责

讲义中曾用简化说法讨论 `_update` 和 `_draw`。整理为公开材料时，需要明确两者的职责：更新处理输入和状态，绘制读取状态并呈现画面。两者都是回调，但不应被教成“完全一样”。

这种区分能帮助学生解释“位置已经改变，为什么看不到”的问题，也能避免把游戏逻辑重复放进绘制函数。调用细节以 [PICO-8 官方手册](https://www.lexaloffle.com/dl/docs/pico-8_manual.html)为准。

## 练习与检查

基础练习是增加上下移动，并回答：为什么 `cls` 后矩形仍能显示？为什么每帧重新赋值会影响持续移动？如果同时按左右键，当前代码会怎样处理？

进一步的练习可以限制矩形不越出画面，再记录最先遇到的边界错误。检查时让学生解释变量变化，而不是只展示代码与示例相同。

## 向碰撞与跳跃过渡

教案随后预备了地图、`mget`、`fget`、物体范围、速度、重力与落地判断。它们适合拆成多个小目标：先判断一个位置是否阻挡，再检查物体范围，最后增加纵向速度。不要把“画面中有平台”直接等同于“角色已经拥有正确碰撞”。

现场教学需要在每个小目标之间停下来确认进度；未完成的内容留到答疑和练习，比同时改变多个概念更容易定位困难。[L02](/teaching/pico8-l02/)继续讨论调试和组织增长中的代码。
